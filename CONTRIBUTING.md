# Contributing to Milan Web Portal Documentation

Thank you for your interest in contributing to the **Milan Web Portal Master Documentation Hub**! This repository serves as the central knowledge base, technical blueprints catalog, and architecture archive for the entire Milan Web Portal ecosystem.

---

## Code of Conduct

We are dedicated to providing a professional, respectful, and collaborative environment. Please treat all contributors, clients, and community members with courtesy.

---

## Documentation Structure & Guidelines

Each project documentation file in this repository follows a standardized, high-value format:

1. **Header & Visual Assets**: Project badge, title typing SVG, preview screenshot, and live production link.
2. **Premium Iskustvo / Overview**: High-level value proposition and metadata table (URL, design style, architecture type, author).
3. **Strategija i Ciljevi**: Problem, Rešenje, and Rezultati breakdown demonstrating tangible client ROI.
4. **Ključne Funkcionalnosti**: Bullet points highlighting core user interactions and features.
5. **Tech Stack & Optimizacija**: Accurate, verified technical stack matching the project repository or workspace folder.
6. **Recenzija Klijenta** *(where applicable)*: Authentic testimonial from project owners or users.
7. **Kontakt**: Official communication channels (website, email, LinkedIn, PayPal support).
8. **The Story & Support**: Creator narrative and support links.

---

## Contribution Workflow

1. **Verify the Source**: Always check the real code in the corresponding project folder or repository before updating documentation.
2. **Encoding & Standards**: Ensure files are saved in clean UTF-8 without BOM. Serbian Latin diacritics (`č`, `ć`, `š`, `đ`, `ž`) must be preserved.
3. **No Unwanted Characters**: Do not use en dashes (`–`) or em dashes (`—`) in body text or punctuation.
4. **Links**: Ensure all links to live domains, repositories, and documentation files are valid and operational.

---

## Conventional Commits

We follow clean declarative commit conventions:

- `docs:` Documentation improvements or additions
- `fix:` Correction of outdated links, specs, or typos
- `style:` Formatting and layout alignments
- `chore:` Repository maintenance
